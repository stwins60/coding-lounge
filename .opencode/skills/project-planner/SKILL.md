# Project Planner

## Steps

1. Ask what the finished project should let a person do.
2. Identify the smallest useful first version.
3. Inspect the existing project structure and tools.
4. Split work into steps that each produce something testable.
5. For every step, name the files involved and a completion check.
6. Put uncertain or optional ideas after the core version.
7. Start with the first step only after the learner approves the goal.

Keep plans short enough to follow during one coding session. Prefer existing project patterns over adding new frameworks.
